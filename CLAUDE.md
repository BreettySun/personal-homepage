# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Hard rules

- **Never run git commands that change state on your own** — no `git add`, `commit`, `push`, `branch`, `checkout`, `reset`, `stash`, `rebase`, `merge`, `tag`, or `remote` changes — unless the user explicitly asks for that specific action in the current message. Read-only inspection (`git status`, `git log`, `git diff`, `git show`) is fine. Finishing a task means leaving the changes in the working tree and reporting them; the user decides when and how they are committed.

## Commands

```bash
npm run dev                                   # Vite dev server
npm test                                      # Vitest unit tests (tests/unit/**/*.test.ts, jsdom)
npx vitest run tests/unit/essays.test.ts      # one test file
npx vitest run -t "groupByYear"               # tests matching a name
npm run typecheck                             # vue-tsc --noEmit
npm run build                                 # prebuild (font subsetting) → vite-ssg build → postbuild (dist/404.html)
npm run test:e2e                              # build + Playwright (projects: desktop, mobile)
npx playwright test -g "terminal" --project=desktop   # one e2e test
npm run test:e2e:update                       # refresh visual snapshot baselines (darwin only)
```

The first `npm run build` downloads two ~24 MB Noto Serif CJK OTFs into `.cache/fonts/` (git-ignored); later builds reuse them. The Playwright visual test is skipped when `CI` is set. Design spec and the original implementation plan live in `docs/superpowers/`; content-authoring rules (frontmatter fields, parser limits) are in `README.md`.

## Architecture

Vite 8 + Vue 3.5 + vue-router 5, prerendered with **vite-ssg** (`dirStyle: 'nested'`) and served from GitHub Pages. Everything a page needs is computed at build time from `content/`; the browser only adds weather, WebGL and interactivity.

**Content pipeline (`src/content/`)** is UI-free. `import.meta.glob('/content/essays/*.md', { query: '?raw', eager: true })` feeds `parseEssay(raw, filePath)`; a hand-written `frontmatter.ts` (flat `key: value` / `key: [a, b]` only, deliberately not gray-matter) plus markdown-it (`html: false`) produce the `Essay`/`Project`/`About` types in `types.ts`. Missing required fields throw with the file path so the build fails loudly. The filename is the slug and the URL; `includedRoutes` in `src/main.ts` expands `/essays/:slug` to one path per essay using the raw (not percent-encoded) slug, filters out the `/:pathMatch(.*)*` fallback, and adds `/404`.

**Terrain (`src/terrain/`)** is the only place that imports `three`. `heightfield.ts` is pure: seeded simplex noise → `Float32Array`, `heightAt()` uses the same function so markers sit on the surface, plus the row LOD helpers (`rowZ`, `rowLevel`, `THIN_DEPTH`/`thinningThresholds`), `EDGE_FADE`/`edgeFade()` and `MARKER_LAYOUT`/`markerLayoutFor(aspect)` (a landscape and a portrait layout, switched at `WIDE_ASPECT`; `tests/unit/markers.test.ts` projects them through the real camera and fails if any entrance leaves the screen or sits under the legend at common viewports — re-run it when moving markers, the legend or the camera). `scene.ts` wires everything and exposes the small `TerrainScene` API (`setSeed/setDensity/setColors/setAltitude/setPointer/setWeather/pickMarker/setHovered/setOpacity/dispose`; `setOpacity` is the intro progress: lines spread out from the centre, markers/clouds/particles fade). The terrain is two geometries sharing one vertex buffer: `LineSegments` (one polyline per grid row, contour look) and a triangle `surface` drawn first that only writes depth — hidden-line removal, so ridges hide the lines, rain and snow behind them. `terrainShader.ts` patches both materials in `onBeforeCompile` with one shared uniform set: row thinning, edge fade, hillshade (`lighting.ts` bakes a per-vertex `aShade` from a light at the upper left; on 宣纸 lit slopes lose ink, on 雨夜 shadowed slopes dim — the direction is picked by comparing line vs background luminance in `setColors`), cloud shadows (the surface paints a faint wash under each cloud's projected shadow, lines cool toward `--muted`), accent ripples spreading from each marker along the contours, and the intro reveal. Two anti-moiré measures must stay: `rowZ()` jitters each row's z by ±15 % of the spacing (seeded, edge rows fixed) so the row period cannot beat against the pixel grid, and the `aLevel` thinning fades odd rows with view depth and every-other-even row further out — a mipmap for lines; `THIN_DEPTH` is calibrated for an 800 px (CSS) viewport and 120 rows and rescaled in `resize()`. Fog and colour tweaks do not fix moiré (they only lower its contrast); density does. `markers.ts` draws the entrances as fixed-pixel-size sprites with the legend's own glyphs (文章 ●, 项目 ▲, 关于 □) on a background-coloured halo, never fogged or occluded, with a thin pin to the ground; picking is a screen-space distance test (`MARKER_HIT_PX`). `atmosphere.ts` is a pure table: per weather state → fog near/far, haze (fog colour blended toward `--muted`) and a line-opacity factor that `scene.ts` eases toward every frame, so clear vs cloudy differ even though neither has particles. `particles.ts` renders rain as short `LineSegments` streaks with a solid head and transparent tail (points fell too fast to read) that splash into small flattened rings where they cross the ground; snow, leaves and catkins are points whose shapes are drawn in the fragment shader (soft discs, tumbling two-pointed leaves, gaussian fluff) with a per-particle `aSeed`; `FALL_SPEED`, `CATKIN_RISE`, `RAIN_STREAK` and `SPLASH` are the knobs. `clouds.ts` is a separate layer, not a particle kind: translucent horizontal patches (canvas radial-gradient texture) drifting above the terrain on any cloudy day, opacity eased and scaled by `intensity`, kept between `AMPLITUDE` and `ALTITUDE.min` so the camera never sits inside them; it also reports each cloud's ground shadow for the shader. `camera.ts` owns `ALTITUDE`, `CAMERA`, `cameraPose()` (also used by `scripts/render-fallback.mjs`), the slow idle `cameraDrift()` and the pure wheel/pointer math so `TerrainCanvas.vue` can import it statically while `scene.ts` is only ever `import()`ed inside `onMounted` — keep it that way, or three.js lands in the Home chunk and in SSR.

**Terrain parameters flow one way.** `src/weather/terrainParams.ts` is a module-level singleton (`useTerrainParams()`) holding `{ weather, season, seed, intensity, density, source }` (`density` is a row-count multiplier for the terrain lines, clamped to `DENSITY.min..max`; the scene rebuilds its geometry via `setDensity`). Open-Meteo (`openMeteo.ts`), the legend's `ParamPanel`, and terminal commands all *write* to it via `setManual`/`applyLive`; `TerrainCanvas.vue` *watches* it and calls the scene API. Nothing else touches the scene. Manual overrides win over live/default and persist in `localStorage['terrain.override']`.

**Theme** (`src/theme/theme.ts`) only sets `data-theme` on `<html>` and `localStorage['theme']`; all colors are CSS variables in `src/styles/tokens.css` (宣纸 light / 雨夜 dark), including `--paper`, the tiled SVG grain painted on `body` (set it to `none` to turn the texture off). The inline script in `index.html` applies the theme before paint. The terrain reads colors through `getComputedStyle`, so new colors must be variables, never literals. Switching goes through `switchTheme()` in `src/theme/transition.ts` (toggle button and terminal): with the View Transitions API and no reduced-motion preference it reveals the new theme as a circle growing from the click point (the new layer is live, so the WebGL terrain recolours inside it); otherwise it applies immediately. Because the theme lands inside the transition's update callback, `data-theme` changes a frame after the click — tests must wait for it, not read it synchronously.

**Terminal** (`src/terminal/`) is a command registry: one file per command in `commands/`, each `{ name, usage, description, run(args, ctx), complete? }`; `registry.ts` aggregates them and `parse.ts` does tokenizing and Tab completion. `help.ts` imports `commands` from the registry (a deliberate, run-time-safe circular import — only as long as the registry is loaded first, so never import `commands/help.ts` directly from elsewhere). `help` separates usage and description with a tab and `Terminal.vue` sets `tab-size` from the widest usage (`displayWidth` counts CJK as two cells), because space padding misaligns as soon as a usage contains Chinese. Add a command by adding a file and listing it in `registry.ts`. The panel is always dark-colored on purpose and is mounted in `App.vue` inside `<ClientOnly>`.

**SSR/hydration rules that bite.** Anything browser-only must resolve after mount and render identically on server and first client paint: `use3d` and `sceneReady` start `false` so SSR emits the static `.fallback` terrain (an alpha mask generated by `npm run fallback` from the real heightfield and camera, coloured with `--fg`; `terrain-fallback-low.svg` matches the phone's low-quality row count) and it stays until the scene reports ready, then crossfades — rerun `npm run fallback` after changing the heightfield, camera, rows or default seed; the legend date and the 404 page's requested path start as `''` and are filled in `onMounted`; `MetaLine` skips empty parts so this stays invisible. `App.vue` sets `useHead({ htmlAttrs: { lang: 'zh-CN' } })` because unhead's SSR default is `en`. The routed `<component>` carries `:key="$route.fullPath"` so essay→essay navigation transitions and remounts (which re-arms the paragraph-reveal observer). `scrollBehavior` in `src/router.ts` returns to the saved position on back/forward and to the top otherwise, but only after `PAGE_LEAVE_MS` — the old page is still fading out (`mode="out-in"`) and would visibly jump; keep it equal to `.page-leave-active` in `base.css`.

## Testing conventions

- Pages/components that call `useHead()` must be mounted with `createHead()` from `@unhead/vue/client` in `global.plugins`, plus a memory-history router built from `routes` when they use the router.
- Module-level singletons (`terrainParams`, `theme`) are isolated in tests with `vi.resetModules()` and a fresh dynamic `import()` per test; stub `fetch`/`matchMedia`/`IntersectionObserver` with `vi.stubGlobal` and restore in `afterEach`.
- e2e runs against `vite preview` of `dist/`, which SPA-falls-back to `index.html` for unknown paths and percent-decodes URLs like a real static host; tests that must hit prerendered HTML use a `javaScriptEnabled: false` context and a trailing slash. `page.keyboard.press('~')` (not `Shift+\``) opens the terminal.

## Deployment

`.github/workflows/deploy.yml` computes `BASE_PATH` from the repo name (`/` for `<user>.github.io`, else `/<repo>/`) and exports it via `$GITHUB_ENV`; `vite.config.ts` reads `process.env.BASE_PATH` as `base`. The e2e step must run with its own `env: BASE_PATH: /` because its preview server also reads that variable. Local `npm run build` uses `/`, so a `/personal-homepage/`-prefixed check needs `BASE_PATH=/personal-homepage/ npm run build`.
